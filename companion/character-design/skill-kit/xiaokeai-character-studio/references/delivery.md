# 成品打包与舞台验收

## 从依赖关系组包

先取当前角色已选中的模型路径和款式，核对定稿时间、模型内名及来源说明。显示名可能相同，多次导入后资源目录可能有数字后缀。打包时从最终模型的依赖表出发，包括漫反射、球面、外部 toon；自定义加载器的 PBR 清单和通道贴图还要按运行时约定收集。用模型所在目录作相对路径基准，保留大小写和目录层级。

可编辑的 Blender 工程另存，执行资源打包并重新打开检查贴图。历史款若要求保留，存放在工程或衣柜里；最终单款 ZIP 只放该款、必需贴图、已有运行清单和随附说明。把定稿复制进临时输出，检验成功后再替换交付文件。

```text
python "<技能目录>/scripts/audit_pmx_zip.py" "<候选角色.zip>"
```

报告列出角色内名、有效面数、PMX 材质引用及小可爱增强清单的覆盖情况。若一个材质有面但当前完全透明、仅用于表情，结合加载器的显示逻辑解释。根据宿主定位其余辅助资源。体积异常时先看报告最大的条目，再查重复模型、旧款、开发源文件和整夹复制的纹理。

## 验收顺序

1. 用正式导入器向干净的测试资源位置导入候选 ZIP。隔离已有同名贴图，核对解包路径、中文显示名、模型内名、作者与底模来源。单纯解压成功只说明 ZIP 可以读。
2. 启动实际前端和资源服务，用新资源路径加载，留意返回 200 却实际拿到前端 HTML 的缺图，以及贴图大小写、着色器编译和透明排序错误。自定义 PBR 依赖宿主读取清单；普通 PMX 查看器通常只显示基础材质。
3. 录下固定姿势的正面、侧面、斜背、仰头和手足近景，播放一个能暴露穿模或脱离的内置动作。比较物理开关与材质开关，确认切换后相机、姿势、表情与所选衣装正常。向用户交付预览时实际打开页面，看见角色再报告。
4. 在有授权的部署中，让现有角色切换到已验证的资源或就地更新相同资产的材质依赖。读回生效路径；若这一步尚未完成，区分“包已验证”和“现有角色已更新”。

一份可复核的交付回答可以很短：链接到可打开的版本、最终包和可编辑源文件；写明在哪个舞台测了哪个动作、实际改到哪些部位，以及哪个效果是近似。若只是局部修改并且用户没有要求重新发包，给相同视角的修前修后即可。
