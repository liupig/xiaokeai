# 小可爱的制作历程与可复用的决定

这是本项目一次实际迭代的索引。下列路径相对含有 `companion/` 与 `online-demo/` 的仓库根；技能包自带的方法与检查工具可以脱离该仓库使用。

## 怎样定下这个角色

1. **起点是完成度参照。** “像心月狐”指东方人物的比例、脸部精致度和骨架质量。最初的长袍版在脸、手、侧脸和后脑轮廓上偏离目标。工作转向从认可的比例出发、局部可回退地精修。用户指胸前图案时，改动单位缩小到图案，先设计再贴到衣面。
2. **发型通过变体收敛。** 从原发衍生可切换款，烟柳低绾得到认可后细修刘海、侧髻与垂感。去除狐耳及旧钗后，仰视暴露出耳根和颅后的空缺，需结合头皮、法线、发底和发际修复。后来的双视图把定稿推进到粉色长卷发和两侧花钗；这两个阶段的审美应分别保留。
3. **衣装由实物感和双视图定型。** 国风短装参考明确了露腿、粉白丝绸、半透飘带和浅金配饰。交领款和后来的玉兰抹胸是独立款。侧视暴露了裙前片和花饰悬离身体，做法是回到身体表面重新拟合布料与饰品。腋下褶皱、两侧轮廓和底衬黑块分别在灰模、斜侧和底面检查。
4. **脸与手采用局部改动。** 从原脸微调下颌和眼型，重绘虹膜，清除左眼附近的痣与左臂字样。把贴图修补、轮廓变化、手指权重分别测试，避免“改发型顺带改脸”。
5. **静态定稿后重新测动态。** 用应用内动作检查抬臂、手臂飘带和转头。末版给长发、鬓发、裙摆和袖带加了 54 根次级物理骨；挥手中途开启物理还涉及 Bullet 的关节初始参考姿势。骨数属于本角色数据，新角色依自己的长度和运动需求划分。
6. **发布与补材质分两次验证。** 曾出现约 914 MB 的打包和舞台导入失败。最终包从实际依赖重新组装，模型名“小可爱”、本版作者“liupig”，保留底模来源。材质先在玉兰花饰验证，再覆盖发束、衣裙、首饰与高跟鞋；审查实际材质槽后才发现身体与甲面仍待补齐。全身版有 39 个物理材质槽、5 个分区皮肤槽，包内 42 个文件、约 52.9 MiB。眉睫、眼部绘制和表情叠层仍走原本的艺术处理。

本地底模 Readme 标注“鸣潮／白泽”，并区分部分优化与二次配布、改作其他角色、拆取部件等限制。项目中的技术实例不能替代素材授权。准备公开发布、商用或跨应用使用的角色，先选允许该用途的素材；分享本技能只需分发方法和脚本。

## 接手原仓库时的入口

下列制作文件位于 `companion/character-design/qingyi/`。先定位当前交付资产，再取所需入口。历史计划中的 GLB 与最终的 PMX 是不同制作阶段。

- **体形、脸、头发。** `build_torso_base.py`、`torso_surface.py`、`yuexiao_proportions.py` 处理形体与比例；`yuexiao_portrait.py` 处理局部眼面；`yuexiao_hair.py` 与 `magnolia_nape_lining.py` 分别负责发束和颅后收口。
- **版型与附件。** `build_yuexiao.py` 组织交领款。抹胸构建入口 `build_strapless.py` 从工作目录里的 `yuexiao.pmx` 派生独立款，调用 `magnolia_fit.py`、`magnolia_satin.py`；`yuexiao_sandals.py`、`yuexiao_jewels.py` 是鞋和饰品的入口。运行前检查输入变体、写入位置和依赖，局部改动可直接从定稿副本开始。
- **物理与可编辑源。** `magnolia_physics.py` 绑定次级链。原工程的 Blender 导出脚本是 `export_lingyun_blend.py`，抹胸参数是 `yuexiao-strapless`；它依赖构建步骤生成的临时编辑版 PMX、项目里的 MMD 插件和已生成的材质文件。
- **全身 PBR 与导入。** `package_magnolia_pbr.py` 接受定稿 PMX 目录、目标 ZIP、通道贴图暂存目录三个位置参数。本例要加载现有设计图集，单独复制该脚本不足以重建角色。舞台绑定在 `companion/frontend/src/engine/magnoliaMaterials.ts`，预览在 `online-demo/frontend/src/main.ts`，正式导入在 `companion/backend/app/services/importer.py`。调出当前角色后，检查真实模型目录旁边的 `xiaokeai-pbr.json`。

## 换一个项目怎样落地

把“玉兰花饰”换成本角色中同时含多种表面的样件，把“挥手”换成能暴露该套衣装问题的现有动作，把 PMX 特有的刚体、toon、清单换成目标格式的对应机制。灰模对照、按实际材质槽盘点、开启与关闭物理的动态对照、从压缩包回导到正式舞台，这四种验证仍可沿用。
