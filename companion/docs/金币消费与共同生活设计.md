# 金币消费与共同生活设计

## 定位

金币是本机自然互动获得的虚拟资源，不提供充值、提现或现实价值。消费用于表达心意、共同布置、开展额外活动和装饰回忆。普通聊天、关心、记忆、生日祝福和安静陪伴始终免费；角色不因用户未消费或离线而变冷淡。

消费闭环：用户主动选择并预览明确内容与价格 → 确认 → 账本扣币并持久交付 → 角色有符合人设的即时回应 → 用户可选择保存回忆 → 在合适的上下文中低频提起。用户可以随时关闭回忆提及、删除记录；删除后不再向模型提供该记录。

## 体验

* 心意：花、饮品、书、画笔和卡片，20–80 金币。用户可附言；显示确定的物品和反馈，不按价格改变角色态度。
* 共同空间：桌面、墙面、窗边与氛围的装饰，120–1200 金币。预览免费，购买永久拥有，可摆放、收起、切换，不重复收费、不因离线消失。
* 共同活动：喝茶、看雨、画画和庆祝，80–300 金币。购买前展示内容，用户可随时结束；普通聊天与静坐仍免费。内容不足时明确说明，不能以静态文字冒充实际演出。
* 回忆：主动收藏、查看、删除及导出免费；相框、贴纸、主题等额外装饰可用金币购买。保存前预览并确认，不自动分享或保存私人对话。
* 免费双向心意：偶尔给用户一张小卡或自然提及相关经历，不以消费为前提，不要求回礼。

不设计付费随机抽取、消费排行榜、离线惩罚、付币和解、角色索要礼物或不可返场的限时商品。节日主题可返场。价格是待验证的初值，既有余额不重置，也不因余额变化对个人涨价。

## 与现有系统的关系

金币由 `backend/native/coins_box.py` 中的加密本地账本管理，经过独立账本进程访问。在线基础产出每分钟 2 金币，连续时长和显存影响倍率；另有聊天和许愿收入。按基础显存倍率从零连续在线计算，30 分钟约 60，1 小时约 150，2 小时约 390；不含聊天与许愿。发布前应在不同设备、使用习惯和已有余额上验证价格，不能以这些示例替代实测。

角色、记忆、相册和场景应按各自现有接口集成，数据保存在本机。用户未授权的互动内容不得写入长期回忆或向外上传。聊天提示只使用用户允许保留的必要摘要，设置频率上限，同一记录至少间隔 14 天，每会话最多主动提及一次；删除记录应立即停止后续引用。

## 交易与恢复要求

商品目录及价格由后端确定，客户端和模型不能决定扣款；确认页面明确显示物品、价格、永久或单次权益。以客户端生成并持久化的唯一订单号发起购买，后端校验商品、余额、角色和所有权。重复请求必须返回同一结果，买断物品再次购买不能扣款。

现有 `pay` 不接受幂等键，且账本与应用数据库不能共享原子事务。不得先调用普通 `pay` 再乐观写入商品：进程在两步之间退出或请求超时重试会导致丢失权益或重复扣款。需要扩展账本原生操作，将订单号与扣款结果在同一次账本持久化中记录，并在账本压缩时保留去重记录；同一订单号如参数不一致必须拒绝。应用先持久化订单，再幂等扣款，随后幂等发货；启动和重试时对未完成订单重新查询账本结果并补发。遇到账本不可用或结果未知时保留订单并提供恢复，不伪报成功或创建新订单。必须验证钱包升级、压缩、并发、进程退出与重试；已有转账和余额不能改变。

## 分阶段验收

1. 礼物、永久装饰、免费回忆卡及购买记录具备完整预览、确认、余额不足提示、权益交付和失败恢复；用户可跳过新手体验。
2. 活动具备真实可开始、退出及复用的演出，角色有可降级的回应；回忆须经用户允许并支持删除和关闭提及。
3. 验证不同角色、无模型或语音失败、桌宠与主界面、多语言、离线、老钱包升级、重启恢复和可访问性。前端构建、后端交易及故障注入测试通过后才视为可交付。

本文件为目标设计；具体功能状态以代码及测试为准。
