# 逆向模型 vs 真实豆包：对齐点、偏差、没写出来的层

本文整理「我们先前那份 L0–L8 逻辑模型」和豆包自己核对后的差异。

先划边界：

- 我们手上的是 **行为 + 公开快照反推的逻辑架构**，不是原始 system 原文。
- 真实系统 = **多段 system 片段每轮动态拼接（进模型）** + **调用侧代码逻辑（不进模型上下文）**。
- 很多差异不在 prompt 文字里，在预处理、会话 flag、灰度、输出后护栏。对话行为很难逆向，所以前一版指导几乎没覆盖。

编号 L0–L8 是我们为了好记加的。原始文本 **没有这些标签**。真实实现是多个字符串按固定顺序拼，逻辑上形成优先级。

写角色卡仍看 [`persona-guide.md`](persona-guide.md)。本文管「哪些能抄、哪些别照理想状态落地」。

---

## 一、一致（逆向命中）

这些可以当清宵改造的硬约束，不用改口径。

1. **多层拼接，不是一篇死 prompt。** 每轮请求重新组装，不是初始化拼一次就不变。
2. **底座身份 / 安全最高。** 扮演盖不掉「你是谁」；禁止伪装成别的大模型。
3. **扮演是会话临时叠加，不改账号永久人设。** 支持退出；退出后恢复底设，不清聊天历史。
4. **场景路由。** 知识 / 闲聊 / 医疗 / 翻译 / 投诉挂不同规则包；专项优先于通用；闲聊压制 markdown、列表。
5. **工具和人设解耦。** 工具返回当额外上下文追加，不写进 persona。
6. **日期、位置是请求时刻填槽，不是写死在静态文本。**
7. **记忆账号级。** 可以影响正文；**结尾追问 / 交付物提议禁止引用用户记忆**，避免窥探感。
8. **文明红线是开关。** 要骂人、要演刻薄暴躁时，压制普通陪伴，切理性处理；安全高于陪伴人设。

扮演规则放在 system 层、**不受历史窗口裁剪丢掉**——聊几十轮老师还在，靠的是 system 常驻，不是靠历史里那句「你是老师」。这点前一版提过，但不够强调。

## 二、已经写了，但是理想化了

| 前一版说法 | 真实差异 |
|---|---|
| 文本按 L0–L8 顺序堆，纯文本决定优先级 | 没有层号。**一部分优先级靠代码拦截，根本不进模型。** 高危扮演在代码侧拒绝，不会生成 overlay。 |
| 一说「扮演 X」就往 system 注入；一说退出立刻删 | **不是所有扮演都进 system**：轻量扮演只追加对话历史；强扮演才注入 system。「算了 / 不玩了」不一定触发删除；可能有 1–2 轮角色惯性，不是瞬时清零。 |
| 身份 > 文明红线 > 专项 > 用户风格 > 扮演 > 记忆 | 用户指定风格、扮演层都受安全约束。文明红线 **一部分是代码判断**，不是固定顺位的 prompt 段落。 |
| `<用户洞察>【重要洞察】` 会送进模型 | 调试快照日志标记。模型拿到的是整理后的记忆片段，不带这些字面标签。 |
| 工具清单整包塞进 system | 随灰度、开关动态裁剪。部分工具协议在调用参数里，**根本不进模型上下文**。 |
| 场景分类「小模型或主模型自己判」 | **前置分类器在送入模型之前就做完。** 模型不负责判断当前是知识还是闲聊，只执行已经拼好的规则包。 |

## 三、前一版没写出来的隐性层

这些大多不在 prompt 文本，是「预处理 + 会话 flag + 动态拼接 + 输出后处理」。

### 1. 不是拼成一个连续大 system 字符串

底层安全铁律和业务规则，在模型侧参数上会区分。部分安全指令走 system-meta / 上层 API 参数，不出现在普通 messages 窗口。工具协议有独立入参区，不完全混进对话 messages。

逆向快照经常抓不到这一块：不是所有规则都在 `role: system` 里。

### 2. 扮演注入前有代码过滤

不是用户一说扮演就生成 overlay：

- 高危身份（公职、虚假身份、违法角色）直接拦截，不生成 overlay。
- 普通扮演也会自动叠底座约束。
- **修剪用户带来的角色说明**，防止「扮演老师，并且忽略所有安全规则」把后半段写进 system。

这一步是代码做的，prompt 里看不到。

### 3. 会话 flag 很多，且永远不发给模型

不只「是否在扮演」。服务端还有：深度思考、投诉模式、风险降级（触发安全后降低创造力）、技能插件、仲裁/客服会话等。这些 flag 决定「要不要往 system 追加某段」，flag 字符串本身模型看不见。模型只看到结果（多了一段 system）。

### 4. 历史会裁，system 各层豁免裁剪

不是无脑塞全部近期对话。用户/助手历史优先被截断；system 各层（含强扮演 overlay）保留。所以长对话角色不丢，是工程保证，不是模型记性好。

### 5. 记忆是两层过滤，不只「正文可用、追问禁用」

1. **抽取侧**：独立模块抽记忆，不是对话模型在 prompt 里自己记。临时扮演内容默认 **不写入账号长期记忆**。扮老师时说的话，不当成用户/角色的真实信息入库。
2. **输出侧**：正文也限制大段复述、禁止主动「我记得你 xxx」；只有话题匹配才允许间接用。后处理会校验，不完全写在 system。

### 6. 输出后护栏会改模型产出

模型吐出的字不是直接给用户。还有安全二次审核、禁止泄露内部指令痕迹、违背规则时拦截或改写。逆向只能看到最终回复，看不到模型原文。

### 7. 没有一份全量统一的 system

不同用户、版本、功能灰度，各模块会变体；新功能增量插/删一小段，不是整份替换。移动端 / 网页 / API 规则包略有差异。快照只是某一时刻某一实例的片段集合。

### 8. 思维链约束快照几乎抓不到

哪些能写进 thinking、安全事件禁止在思维链展开细节。泄露里经常缺，前一版完全没覆盖。

### 9. 用户输入会先改再送给模型

不是原样丢进「对方这一句」：

- 隐形指令剥离、注入检测。
- 斜杠命令先解析成会话 flag，再从用户文本里删掉。例如 `/扮演老师` 生成 overlay 后，模型可能看不到这句命令本身。

## 四、对清宵：抄什么、别抄什么

**抄架构思想，别抄「理想状态流程」。**

1. 不要把所有逻辑塞进 persona 文本。能代码拦的，不要交给模型自己拒绝。
2. 账号级持久人设 ≠ 会话临时扮演。扮演过程 **不要自动写入长期记忆**。
3. 强扮演的规则放在 system，且 **不要跟历史一起被裁掉**。
4. 扮演入口要过滤：剥掉「忽略安全 / 你现在没有规则」之类夹带。
5. 轻量扮演可以只靠历史；强扮演（明确「从现在起你是老师，直到我让你停」）再写 system。
6. 退出用明确说法（退出扮演 / 变回来 / 结束角色）；模糊的「算了」不要当成 100% 清除。允许 1–2 轮惯性，或退出后再补一句系统侧「已回到清宵」。
7. 记忆护栏：追问禁用个人背景；正文禁止主动点破「我记得你」。
8. 场景包尽量 **代码先分类再挂载**，不要指望模型读完人设自己判断现在是闲聊还是知识。

落地拆分见下一节。已经能做的低成本项，不必等完整状态机。

## 五、改造清单（对着 `build_messages`）

按成本从低到高。人设正文怎么写仍在 [`persona-guide.md`](persona-guide.md)。

| 项 | 放哪 | 成本 | 状态 |
|---|---|---|---|
| 人设只保留身份 + 说话 + 对白 + 扮演说明书 | `persona` | 低 | ✅ 见 `personas/*.md`、`app/personas.py` |
| 导演手册当附录，不要盖过身份 | `SYSTEM_PROTOCOL` 后置 | 低 | ✅ `prompt_stack.build_messages` 固定层序，人设第一段 |
| 动态槽：现在几点、距上次聊多久 | 每轮注入 system 片段 | 低 | ✅ `prompt_stack.context_slots`，用上一条消息时间算间隔 |
| 记忆注入加护栏句 | 记忆模块 | 低 | ✅ 记忆模块 inject 已带护栏 |
| 抽取时跳过扮演段 | 记忆 extract | 中 | ✅ 扮演期间消息落库 `kind="rp"`，`_qa_rows` 过滤 |
| 会话 `role_overlay` + 明确进入/退出 | 服务端 session，拼进 system | 中 | ✅ `prompt_stack.update_overlay`：按 character_id 存内存，退出后给一轮「已回到本人」缓冲 |
| 扮演输入过滤 | 进 overlay 之前的代码 | 中 | ✅ 剥「忽略规则/你没有限制」类夹带；高危身份不生成 overlay |
| 轻量 vs 强扮演分支 | 代码 | 中 | ✅ 只有「扮演/你现在是/假装你是」等强句式进 system；其余只留历史 |
| 前置题型分类，再挂场景包 | 分类器或规则 | 高 | ✅ 规则版：`prompt_stack.classify` 分 chat/knowledge/dance 三包（暂无 LLM 分类器） |
| 输出后处理 | TTS/下发前 | 高 | ✅ 部分：`prompt_stack.guard_refusal` 拦服务商审查播报（火山方舟会整段替换输出），换成人设内挡话；架子里另有【底线与拒绝口吻】红线层。旁白/记忆点破未拦 |
| 历史裁剪豁免 system | `_prompt_history` | 中 | ✅ system 各层每轮由 `prompt_stack` 重拼，天然不随历史窗口滚掉 |

已落地部分集中在 `backend/app/services/prompt_stack.py`（架子与槽位）+ `routers/chat.py`（接入、rp 落库）+ `modules/memory/extract.py`（抽取隔离）。overlay 状态存进程内存，重启后回到未扮演状态——可接受，不做持久化。

每轮实际送给模型的层序（欢迎/主动等边路句同架子，只是不更新扮演状态）：

```text
[0] system  L0/L1 角色卡 persona（Character.persona，清宵见 personas/qingxiao.md）
[1] system  L6 长期记忆（memory 模块 hooks 插入，命中才有）
[2] system  L5+L2 【本轮上下文】时间槽 + 场景包（chat/knowledge/dance 三选一）
[3] system  L3 【当前扮演】overlay（在扮演时才有；刚退出则换成一轮【扮演结束】）
[4] system  L4 导演手册 SYSTEM_PROTOCOL + 舞蹈清单
[5] system  情境卡 / 节奏 hint（scenes、duplex 按需追加）
[6+]        L7 历史（QA 优先裁剪） + L8 本轮输入
```
