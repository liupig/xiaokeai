# 把 dsh 收成聊天代理

2026-10-28。这篇只写一件事：DeepSeek Harness（`dsh`）本来是编程代理，小可爱怎么让它负责开口。版本里还有一起看、打包、物理，那些在 [20261028技术更新](./20261028技术更新.md)。这里不重复。

内核版本是 `deepseek-harness-sdk==0.2.1rc2`。没有改它的二进制，也没有维护一份 harness 源码。变的是宿主怎么启动它、往 profile 里补什么、一轮里送进去和拿出来的是什么。

## 原样的 dsh 是什么

dsh 是一套编程代理运行时。它自己管会话、技能目录、工具循环和上下文折叠。模型每轮先看见技能的名字和 `description`，对上了才读正文。工具做完，结果再喂回去，直到这一轮停。

拿来当陪聊的嘴，这些默认是碍事的：

| 编程代理的默认 | 开口时会怎样 |
|---|---|
| 思考力度不传就是 `high` | 闲聊先写一大段推理，第一句出不来 |
| 没填长度上限就带 256000 | 方舟超过 131072 直接 400 |
| 自动折叠 | 开口前同步写一份摘要，模板是编程纪要 |
| `web_search` / `web_fetch` | 自己去打开网页，和宿主的查法叠在一起 |
| 技能先加载再说话 | 闲聊多一次工具往返 |
| 工作目录指向项目 | 改文件、跑命令会碰到仓库 |
| 系统提示会提到技能名单 | 这些字会被念出来 |

它也不会比直连 `chat/completions` 更快。官方 DeepSeek 插件就是一次请求再解 SSE，和原来的 httpx 流式是同一类传输。选它是因为会话和技能目录可以长驻，不是因为传输更快。

旁边的 Cursor、Codex、Claude Code、通义灵码、Trae、文心快码仍是用户自己的工人。Code 伴侣只读它们的开工和收工。没有把其中一家的 CLI 换成她的嘴：那些工具面是文件和补丁，系统提示是编程代理，账号也不是设置里那把对话密钥。

用的是长驻的 `dsh --profile sdk`，不是 `headless`，也不是 `dsh web`。`headless` 每句新开会话再退出，闲聊付不起。SDK 自带 runtime，打进 A 包，用户不用另装 Node。`dsh_home` 显式给到 `data/dsh`，不碰用户的 `~/.dsh`。

## 聊天代理要它做什么

舞台、口型、全双工、表演标记解析仍是小可的。dsh 只负责想和说。说出来的正文必须还能被原来的管线用：短口语，开头带 `[emo:]`，镜头和动作写成标记，不要 markdown。

一件事要不要做，分成两种。

**直接开口。** 闲聊、看牌、画画。规矩写在系统提示里，模型不要为它们调用 skill。标记由宿主执行：`[emo:]` `[cam:]` `[dance:]` `[draw:]` 仍进现有解析。发牌、出图不是模型做的。

**调用一次再开口。** 跳舞、核对现况、看屏幕。模型调用对应技能，正文里写一个标记，宿主去做，做完再送一轮。宿主不另写「这句像不像在跳舞」的分类器。路由仍是技能目录。当前内核给模型看的目录没有 `whenToUse`，所以「什么时候用」写在 `description` 里。

许愿、问余额不进目录。口头那句在进模型前就被认走，枚数和余额由账本算。

## 改了哪几层

### 1. 进程和目录

模块 `harness` 打开后拉起一次子进程，关掉模块或退出程序再收掉。一条角色一条会话，名字是 `xiaoke-{角色 id}`。看牌进行中的那句也进这条会话，目录才能看见牌在【现场】里。

技能原文在 `app/modules/harness/skills/`。启动时抄到 `data/dsh/skills/`。正文变了才覆盖。工作目录是旁边的空 `dsh/workspace`，不指向安装目录，也不指向源码仓库。会话、账本、日志都在 `data/`，不进 git。

Windows 上还有一处和聊天无关、但不起进程就说不了话：cwd 不在 `C:` 或 `V:` 时，快照里的 koffi 加载失败。会话目录仍留在数据目录，子进程自己的 cwd 改到 `C:` 上的空目录 `xiaokeai-dsh`。

子进程自己退出（管道断开、连接重置这一类）时，这一轮报错，不退回 `llm.py`。下一句重新拉起。

### 2. profile 补丁

同步技能时写 `data/dsh/profiles/sdk/cordis.patch.yml`。只补三处：

- `compaction-basic.auto: false`。自动折叠会挡住第一句，摘要也不是口语。
- `tool-web` 的 `search` 和 `fetch` 关掉。联网只认正文里的 `[lookup:]`。
- `system-prompt.personaPrefix` 里放上口吻，以及 `chat`、`tarot`、`draw` 的正文。这三条的 front matter 写着 `disable-model-invocation: true`，`description` 也写「不要调用」。

`dance`、`lookup`、`watch` 不放进这段前缀。它们仍要调用，调用了才读正文。一起看关着时，补丁里不提 `watch`，磁盘上上次留下的那份也删掉。

补丁没有关掉文件和命令工具。挡住它们的是技能正文里的「不要改文件，不要跑命令」，以及工作目录是空的。这不是沙箱。模型如果仍然去改，改到的是 `data/dsh/workspace`，不是仓库。

### 3. 一轮里送进去的字

宿主把已经叠好的系统提示收成【现场】：身份、底线、时间、记忆、情境。导演手册不再抄进去，标记规矩在 `chat` 的正文里，选中才读。舞蹈文件名只在不是看牌的时候附上，最多 48 个。

送给 dsh 的用户文本是三段：

```text
【刚说过】
对方：…
她：…

【现场】
身份、记忆、情境。看牌时还有这一轮该讲的牌。

【这句】
对方刚刚说的话
```

【刚说过】只留最近十轮。更早的在宿主记录和 mem0 里。

第一句会把人设和舞蹈名单种进会话。种过之后，普通轮不再贴这两段。看牌例外：【当前扮演】或【这一轮任务】每轮仍带，因为桌上的牌会变。同一段现场反复送，短句会越来越慢。

会话大约在第 53 句开始折叠，折完仍贴着触发线，后面几乎一句一折。宿主在写到 36 句时先换一条新会话（`xiaoke-{角色 id}-{代}`），下一句重新带上最近十轮，不接着那份编程摘要。

思考和长度按设置走。设置里思考关，传 `off`；开，传 `high`；跟随默认就不传，那时 dsh 自己是 `high`。方舟没填上限时，思考关用 2048，思考开用 8192。填了又超过 131072 的，裁到 131072。别的服务商没填，仍交给对方默认。

地址也要改一层。设置里是 OpenAI 兼容地址，dsh 的适配器走 Anthropic Messages，钥匙放在 `x-api-key`。方舟的 `/api/v3` 改到 `/api/compatible`，带 `/v3` 的 coding 和 plan 去掉末尾的 `/v3`。DeepSeek 官方的 `/v1` 改到 `/anthropic`。豆包角色模型的模型名没有 Messages 权限，要填 `ep-` 开头的接入点，填模型名会在开进程前拒绝。

### 4. 拿出来的字

dsh 的通知里，推理和工具参数不算要念的话。`TextGrowth` 只交出助手正文的新增部分。`TagStreamParser` 再把 `[emo:]` `[cam:]` `[dance:]` `[draw:]` `[lookup:]` `[glance:]` 拆成事件，正文进全双工和 TTS。

`SpokenGate` 收成一句再放行。整句里带「技能」「system-reminder」「available_skills」这一类字的，不送进语音。标记本身不会被念出来。

## 一轮闲聊怎么走

用户开口，并且不是重说、不是看牌收摊后那句，才进 dsh。欢迎、沉默续聊、告别、摸一下、Code 伴侣仍走原来的 `stream_chat`。失败不悄悄退回。

```text
对方这一句
  → 账本先认走许愿和「一共多少钱」
  → 拼【现场】【这句】
  → dsh 会话 xiaoke-{角色 id}
  → 正文增量
  → 标记解析 → 全双工 → TTS
```

点舞时宿主先说出「好，我跳一支。」这一类铺垫，再把「不要重复，先调用 dance」写进【这句】。模型回来后补一句，并写 `[dance:]`。名单在【现场】里，不在技能正文里。

对方这句已经说出要画什么时，舞台先开口并亮牌，【这句】里注明不要再写 `[draw:]`。图是火山 Seedream，竖向 1024×1536。模型只负责按画面说，不宣布已经画好。

看牌时发牌、正逆位、洗切翻都是代码。【现场】写这一轮该讲哪张，模型只讲那张。名字用玉币、竹杖、瓷盏、古剑。它说了不算数的那些动作，技能里写明不要自己做。

## 查和看仍是两轮

这两件事不能在第一轮里编。第一轮只许铺垫和标记，事实等宿主做完再送回来。

**查。** 模型写 `[lookup:检索词]`。检索词由它改写，宿主不改。第一轮正文里如果没有「我去查一下。」，宿主补上，并丢掉这一轮里抢着报的数字。宿主用浏览器请求头查必应、360、谷歌，不查百度和搜狗，也不调用已经关掉的 `web_search`。查完再进同一条 dsh 会话，【现场】是页面上的事实，【这句】要求把事实说完，不要再写标记。检索词是「还有」「吗」这种不能查的，会再要一次，只许写标记。

**看。** 一起看开着，模型写 `[glance:]`，或者对方那句本身就是「在干嘛 / 在哪 / 一起看」而模型没写标记，宿主仍去看。第一轮先说「我看看。」，同时向 `127.0.0.1:8766` 要观察。观察回来之后，反应这句走的是原来的 `stream_chat`，不是 dsh。系统提示里带上【眼前】，用户内容是「就接这一句」。空话、只说「我在陪着」的，丢掉，嘴里留下「我看看。」。

`brief.py` 里 `wants_harness()` 把 `mode=along` 和 `mode=user` 写在一起，注释也写着画面变了的那句进同一条会话。路由里 `mode == "along"` 排在 harness 分支前面，实际调用的是 `stream_chat`。所以主动陪看的那一句，现在并不在 dsh 里。用户自己说「一起看」的第一轮才在 dsh 里。

## 还没收成嘴的部分

- 欢迎、沉默续聊、告别、摸一下、Code 伴侣、重说，仍是旧接口。两套提示还在。
- 主动陪看，以及看完屏幕之后的那句反应，也是旧接口。
- 文件和命令工具没有在补丁里关掉。
- 只有整段 `assistant/message`、没有增量时，第一句要等这轮闲下来。
- 用户开口和 dsh 上的另一轮共用同一把锁。查网页的第二轮还占着这把锁。
- 内核仍是 `0.2.1rc2`。下次换版本，改 `requirements.txt` 再打包。profile 补丁和技能文件是升级时还跟得上的那一面。
