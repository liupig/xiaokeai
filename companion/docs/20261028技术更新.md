## 为什么基座是 dsh

小可爱旁边已经认识六家编程代理：Cursor、Codex、Claude Code、通义灵码、Trae、文心快码。Code 伴侣只读它们留在本机的开工和收工，默认看 Cursor 的 transcript。那六家继续当用户自己的工人。嵌进「她开口」这条链的，是 DeepSeek Harness，命令行名字是 `dsh`。

选它，不是因为它更会写代码。比较的是：能不能当成一个长驻进程，用已经填在设置里的对话密钥说话，技能用仓库里的 Markdown 加进去，并且打进 A 包时不用再装一套 Node。

接进去之前对过四种用法：

| 用法 | 每一句要付的代价 | 当时的判断 |
|---|---|---|
| `codex exec` | 每次新起一次 app-server。近版本大约 2 秒，更早的回退版本到 5–7 秒 | 不适合每一句闲聊 |
| `dsh --profile headless` | 每次新会话，跑完就退出 | 同样不适合 |
| `codex app-server` 一直挂着 | 启动付一次 | 进程模型可用，账号是 ChatGPT 登录，工具面是文件、命令和补丁 |
| `dsh --profile sdk` 一直挂着 | 启动付一次 | 用这一条 |

Windows 上如果走官方 npm 包，第一次解开很重，冷启动到就绪大约 19–31 秒，同一份安装再开大约 3 秒。源码里的 TUI 启动大约 0.7 秒。这些数字是接入时对公开包的观察，不是这一版体验包的开口成绩。产品里不走那条 npm 冷启动：PyPI 上的 `deepseek-harness-sdk==0.2.1rc2` 自己带同版本 runtime，可执行文件在 `site-packages/deepseek_harness_runtime/runtime/`。打 A 包时跟别的 Python 依赖一起复制，用户不用另装 Node，也不碰自己的 `~/.dsh`。

Codex 没有拿来当每一句话的嘴，有三个具体原因。

1. 它的工具是改仓库。小可爱要的工具是讲已经摊开的牌、按画面开口、查一句天气、看一眼屏幕。这些结果必须交回现有的标签解析和全双工，而不是交回一个补丁。
2. 它的系统提示是编程代理。短口语、不要 markdown、开头带 `[emo:]`，和那套提示放在一起不稳定。
3. 账号是另一套登录。小可爱的对话密钥已经是 OpenAI 兼容地址，dsh 可以吃同一把钥匙。Codex 不能。

Claude Code、Cursor 这些同理：它们是用户桌面上的工人，Code 伴侣旁观它们。把其中一家的 CLI 换成「她的大脑」，会把人设、塔罗、记忆再塞进一个编程循环里跑一遍。

当时也明确过另一件事：dsh 本身不会比直连 `chat/completions` 更快。DeepSeek 插件对官方接口就是一次 `fetch` 再解 SSE，和原来的 httpx 流式是同一类传输。别人测到一百多 token 每秒，快的是 `deepseek-v4-flash` 并且把思考关掉，不是 harness 这个进程。dsh 不传参数时，自己的默认是思考力度 `high`、输出上限很大。那样闲聊会先写一大段推理再开口。所以后面的改动是把这条默认压掉，而不是指望换运行时就变快。

内核按它自己的版本升级。小可只站在公开的那一层：Python SDK、长驻的 `dsh --profile sdk`、换行 JSON-RPC、显式的 `dsh_home`。不跟 harness 的 master 源码，也不改 Cordis 里的实现。技能文件和 SDK 调用是升级时还跟得上的那一面。

## dsh 在这一版里怎么用

模块 `harness` 打开后，后端拉起一次子进程，关掉模块或退出程序再收掉。不开 `headless`，也不开 `dsh web`。

```text
用户开口
  → 宿主拼【现场】【这句】
  → 同一条会话 xiaoke-{角色 id}
  → dsh 按技能目录决定直接说，还是调用 dance / lookup / watch
  → 助手正文流进原来的标签解析、全双工、TTS
```

一条角色一条会话。看牌进行中的那句也进这条会话，目录才能选中 `tarot`。失败就在这一轮报错，不悄悄退回 `llm.py`。子进程要是自己退出了（管道断开、连接重置这一类），下一句重新拉起。

技能原文在 `companion/backend/app/modules/harness/skills/`。进程起来时抄到 `companion/backend/data/dsh/skills/`。这个目录是这次运行的 `DSH_HOME`。工作目录是旁边的空 `dsh/workspace`，不指向安装目录，也不指向源码仓库。`data/` 不进 git。

| 技能 | 这一版谁来做 |
|---|---|
| chat | 闲聊和表演标记。正文写进系统提示，模型直接开口，不先调用 skill |
| tarot | 只讲已经摊开的牌。发牌、正逆位仍是代码 |
| draw | 按画面开口，写 `[draw:画面]`。对方这句已经说出画面时，舞台先把这句话说出来并开画 |
| dance | 对方点名要跳才调用。铺垫由宿主先说，文件名仍在【现场】 |
| lookup | 模型写 `[lookup:检索词]`。宿主查必应、360、谷歌，不查百度和搜狗 |
| watch | 只有一起看开着才抄进目录。模型写 `[glance:]`，宿主向 `127.0.0.1:8766` 要一句观察 |

许愿不是技能。口头那句在进对话前就被认走，池子、道具和枚数由账本算，模型只补一句必须带上这个整数的旁白。说错就丢掉。

路由仍然是 harness 自己的技能目录：每轮只看见名字和 `description`，对上了才读正文。宿主不另写「这句像不像在看屏幕」的分类器。当前内核给模型看的目录没有 `whenToUse`，所以「什么时候用」写在 `description` 里。

密钥用设置里已有的 AI 对话。SDK 把 `api_key` 放进子进程。模型名用设置里的。地址要改一层，因为 dsh 的官方适配器走的是 Anthropic Messages，钥匙放在 `x-api-key`，而设置里存的是 OpenAI 兼容地址。`messages_base()` 做的就是这件事：方舟的 `/api/v3` 改到 `/api/compatible`，`/api/coding/v3` 和 `/api/plan/v3` 去掉末尾的 `/v3`；DeepSeek 官方的 `/v1` 改到 `/anthropic`。豆包角色模型的模型名没有 Messages 权限，Harness 开着时要填方舟接入点，`ep-` 开头。填模型名会直接拒绝，并提示去改设置。

## 对 dsh 改了什么

没有改 runtime 的二进制。改的是宿主怎么启动它、怎么写 profile 补丁、怎么裁一轮里送进去的字。

### 进程能在非 C 盘的仓库里起来

Windows 上，进程当前目录不在 `C:` 或 `V:` 时，快照里的 koffi 会加载失败。会话目录仍留在数据目录。子进程自己的 cwd 改到本机 `C:` 上的一个空目录（`LOCALAPPDATA`、临时目录或系统目录下的 `xiaokeai-dsh`）。这是运行时的已知问题，不是小可的会话格式。

### profile 补丁

每次同步技能时，写 `data/dsh/profiles/sdk/cordis.patch.yml`。三处：

- `compaction-basic` 的 `auto` 设为 `false`。自动折叠会在开口前同步写一份摘要，模板还是编程纪要。闲聊用不上，而且会挡住第一句。
- `tool-web` 的 `search` 和 `fetch` 关掉。联网走宿主的 `[lookup:]`，不走内核自带的网页工具，仓库里也不放搜索密钥。
- `system-prompt` 的 `personaPrefix` 里放上 `chat`、`tarot`、`draw` 的正文。这三条不再让模型先加载技能再开口。`dance`、`lookup`、`watch` 仍是调用。一起看关着时，补丁里不提 `watch`，磁盘上留下的那份技能也会删掉。

另外写了一条口吻约束：系统提醒、技能名单、技能名字和推理过程不要说出来。流式正文再过一层 `SpokenGate`，整句里带「技能」「system-reminder」这一类字的，不送进语音。

### 会话不要越聊越长

dsh 这条会话大约在第 53 句开始折叠。折完仍贴着触发线，后面几乎一句一折。宿主在第 36 句之前先换一条新会话（`xiaoke-{角色 id}-{代}`），下一句带上最近十轮，不再接着那份旧摘要。最近十轮是 `RECENT_ROUNDS`。更早的对话留在宿主自己的记录和 mem0 里，不整段灌进 dsh。

第一句会把身份、舞蹈名单和最近对话种进会话。种过之后，普通轮不再把人设和舞蹈名单再贴一遍。看牌的【当前扮演】【这一轮任务】每轮仍带，因为牌会变。短句越来越慢，有一部分就是同一段现场被反复送进去。

### 思考和长度上限按设置走

`reasoning_effort_for()`：设置里思考关，就传 `off`；开，传 `high`；跟随默认，就不传。不传时 dsh 自己是 `high`，闲聊会先写推理。

`turn_max_tokens()`：设置里没填上限时，不要按接口天花板去要。dsh 空白会带 256000。方舟超过 131072 直接 400。所以方舟在没填上限时，思考关用 2048，思考开用 8192；填了又超过 131072 的，裁到 131072。别的服务商没填就仍交给对方默认。

### 宿主先说的那半句

点舞时，宿主先说出「好，我跳一支。」这一类铺垫，再让模型调用 `dance`。画画时，对方这句已经带了画面，舞台先开口并亮牌，不等模型把整段写完。图的尺寸用竖向 `1024x1536`，不要求 2K。牌在屏幕上大约两百像素，放大也不过一千。等图的时间是火山出图，不是 dsh。接入时量过：一张 2K 要几十秒（一只白猫大约 32 秒，红衣剑客大约 56 秒），开口本身大约 7 秒。改尺寸会短一截，做不到秒出。

### 两套大脑不要同时答一句

`wants_harness()` 只放行 `mode=user` 和一起看的 `mode=along`。重说、收摊后那句、欢迎、续聊、告别不进。一起看的主动一句也进同一条会话，不走旧的 proactive。那条还在旧模型上，两套会各说一句。

## 速度：慢在哪，改了哪

开口变慢，不是舞台渲染。10 月 22 日之后有一轮本机对话日志可以对着看，那不是对照组实验，只说明当时差在哪一条路上。同一分钟里，走 dsh 的「叫爸爸」大约 4.2 秒才出第一个字，「真乖哟」大约 5.8 秒。走原来接口的续聊大约 1.2 秒，道别大约 1.1 秒。思考开关当时是关的，所以不是模型在默默写一段长推理。慢的是开口前那一下，以及旁边还占着同一条会话的活。

当时对得上的原因，和后来改掉的地方：

| 现象 | 原因 | 这一版的处理 |
|---|---|---|
| 短句也要数秒才出第一个字 | 上限是 0 时，曾经向方舟要 131072 | 方舟没填上限时改为 2048 或 8192 |
| 闲聊先写一大段再开口 | dsh 默认思考力度 `high` | 设置关思考就传 `off` |
| 聊得越久越慢 | 每轮重贴人设；第 53 句后几乎一句一折 | 种过会话不再重贴；第 36 句换新会话；关掉自动折叠 |
| 闲聊多一次工具往返 | 先加载 skill 再说话 | `chat` / `tarot` / `draw` 的规矩放进系统提示 |
| 用户一句要等陪看那轮跑完 | 同一条 dsh 会话、同一把轮次锁 | 锁还在。眼睛和钱包改到别的进程，不再占聊天进程的 SQLite 和解释器 |
| 「我看看」之后又等一眼 | 第一轮只出标记，第二轮才带观察。眼睛一眼在试验里大约 5 秒，超时放到 180 秒 | 能用窗口文字或系统声说清的，不再叫 1B。画面没变不送模型 |
| 本地 Qwen 预热卡住，不能开口 | 语音和眼睛要的 transformers 不是一版 | 语音改到 5.20.2 的兼容分支，和眼睛共用一套 PyTorch |
| 出图要等半分钟才说「画好了」 | 2K 出图慢，而且「画好了」说在图到之前 | 先说正在画什么，图到了再说「好了，你看。」尺寸改为 1024×1536 |

还有两处是「别的活不要堵住说话」，不是把模型变快。

钱包的加密、重放、写库放到单独进程 `ledger_proc.py`，标准输入输出一行一个 JSON。SQLite 打开 WAL，`busy_timeout` 3 秒，事务结束就放开锁，不再把连接挂在整段语音上。提交 `55a2c73` 的目的就是：钱包和眼睛在干活时，聊天、语音和舞台照常动。

本地 TTS 本来就在独立 GPU 进程里，和 SenseVoice、FastAPI 不共用解释器。卡住的是加载。官方 `qwen-tts` 的元数据写着 `transformers<5`，MiniCPM-V 4.7 要 `transformers>=5.18`。两套装进一个环境，语音那一侧会加载失败或预热不回来。2026-10-28 改用 dayn9t 的未合并分支 `fix-transformers5-compat`（`488343c`），钉在 `transformers==5.20.2`。当时测过：0.6B CustomVoice 能加载，流式合成「你好。」出了大约 1.9 秒音频。这是加载成功的一次测量，不是开口延迟的承诺。`qwen3-tts-streaming` 的元数据仍写着 `transformers<5`，运行时用的是已经装上的 5.20.2。

MiniCPM-o 4.5 的本机 PyTorch 要 `transformers==4.51.0`，装进来会把 5.20.2 降坏，所以它仍然不进这个进程。设置里的 Omni 继续是云端或自建 Gateway 的测试口。

还没有拿掉的延迟也写在这里。dsh 一轮如果只有整段 `assistant/message`、没有增量，开口仍要等这轮闲下来。一起看和用户开口共用同一条会话和同一把锁，她正在为画面生成时，下一句用户话要等那一轮结束，哪怕最后一句被滤掉也占着。眼睛超时仍是 180 秒。这两条在 10 月 28 日的包里还在。

## 桌面识别怎么选的

一起看要补的是她缺的那双眼睛，不是再换一个会说话的人。人设、记忆、表演标记、全双工已经在。dsh 负责想和说。新感知只允许变成一句短文本，放进【眼前】。

这条边界在更早的陪玩施工图里就写过：新模型不进当前 Python 进程；感知不直接拧骨骼；她可以评论屏幕，不代点、不代打。10 月 23 日的接法说明把眼睛定成 MiniCPM-V 4.7 1B。10 月 25 日先接上口头三句。10 月 27 日把「每一眼都让 1B 看整屏」改成现在这三路。

### 看过、没用成主路的

**把图直接交给会说话的那个模型。** 开源里 Wallie 把这件事写得最清楚：大约 3 秒一张截图，长边大约 768，图进同一个会说话的模型，中间不经过一个字幕员。它再用一层注意力决定深反应、扫一眼、扯一句自己的事、故意不管，还是留白，并可以用 `SKIP`。系统声走 WASAPI 环回。这套「没具体东西可说就别开口」是对的。没有搬过来的是两件事：图进主对话模型，以及说话的人站在主播立场（「我被 boss 打飞了」）。小可爱是坐在旁边的人。dsh 这一条会话看不见像素，把像素塞进会话没有用。用 1B 替换主对话也不成立，它的骨干是 Qwen3.5，纯文字只够短句，人设和表演会变薄。

**把整段视频交给云端，要一份带时间戳的反应脚本。** AI Watch Buddy 是这条：不截桌面，整段片子给 Gemini，模型吐某秒说话、暂停、拖回去重看。用户一插话，未执行的脚本作废。它能卡在那一拍上，是因为它能暂停片子。小可爱看的是用户自己的播放器，不能替他暂停，也不能把片子上传。所以没有走脚本。

**用界面树去点。** OmniParser 一类的方案能找出按钮再点击。施工图和这一版都明确不做代操作。Code 伴侣继续只看本机 transcript，不负责去点 IDE。

**把 MiniCPM-o 4.5 装进后端。** 上面已经写了 transformers 版本。摄像头现在是 MediaPipe 动捕，占的是骨骼，不是「看懂你」。两路不要抢同一只摄像头。「看看我」这一版没有接。

**每一眼都让 1B 填一张整屏表。** 这是 10 月 25 日第一刀的形状：窗口、类型、标题、原文，理解层再抽一行，塞进最多大约 700 字的【现场】。字经常是看错的。台词和歌词很多不在像素里，在声里。眼睛超时按几十秒计。闸门再严，她也只能复述字幕，或者因为没有可交的点一直闭嘴。10 月 27 日改的就是这一段的来源，不是改 dsh，也不是改表演。

### 落地的三路

一次观察由三路拼成，进对话的仍是短文本。代码在 `glance/sense.py`、`glance/desktop.py`、`glance/hearing.py`，眼睛进程只负责看图。

```text
前台窗口（Win32）── 进程、标题、焦点和子窗口里的字
        │
系统声（环回）──── 台词、歌词。她自己在说的时候不听
        │
裁切后的画面 ──── 只有上面两路还没有新事实、而且这块画面动了，才送 1B
        │
        └→ 一句【眼前】→ 理解层决定有没有值得交的点 → 同一条 dsh
```

**窗口。** `GetForegroundWindow` 读进程和标题。前台如果是小可爱自己，或是输入法空窗（`Default IME`、`MSCTFIME UI` 这一类），沿 Z 序往后找下一个可见窗口。一起看时如果前台是陪看记录页或编辑器，还会再找标题里带 B 站、YouTube、抖音的那一窗。代码、幻灯片、文档、浏览器外壳的正文用焦点控件和子窗口文字，最多留 4 条。读不到就空着，不编。这一路不去点，也不改焦点。

**声音。** 装了 `soundcard` 才有扬声器环回。没有环回设备，这一眼就当没有声音。她开口时把这段听筒清掉，避免把自己的 TTS 听成台词。听到的句子大约留 18 秒。电影、歌、视频里值得交给她的那一句，优先用按张认出的字幕；没有字幕才用听到的。

**画面。** 眼睛进程在 `127.0.0.1:8766`。抓屏优先 DXGI（`bettercam` 的 Desktop Duplication）。`mss` 底层是 BitBlt，经常抓不到浏览器里硬件解码的视频，所以只做失败后的退路。试验时还见过另一种失败：整屏一平均，会把小窗口里的变化当成没变。所以送给模型的不是整桌面，而是前台窗口那一块矩形。宿主这边用窗口矩形做 8×8 感知哈希，汉明距离大于 8 才算动了。哈希只决定要不要再送模型，不代替眼睛看内容。

什么时候才叫 1B，写在 `should_call_eyes()`：

- 让她在屏幕上找东西：必须看图。
- 代码、稿子、幻灯片已经读到正文：不看。
- 浏览器已经有标题或正文：不看。
- 音乐已经有标题、歌词或听到的一句：不看。
- 编辑器读不到正文：只在换窗口，或到了该场景的最大间隔时看，不跟着每一次击键看。
- 电影、视频、游戏：画面动了要看；画面很静，到了最大间隔也要看。间隔在 `watch.py`：电影 12 秒、代码 18 秒、音乐 8 秒、视频 5 秒、幻灯片 15 秒、游戏 8 秒、不确定 10 秒。

选本机 MiniCPM 时，由眼睛进程里的模型看这些图。选别的视觉模型时，眼睛只交出原图，小可爱再按 OpenAI 兼容接口把图发出去。无论哪一种，返回给对话的字典都会把像素丢掉。调试记录可以在本机留最近的图，那一页从设置里打开，启动时不弹。

1B 的提示只要求写看得见的事实：窗口、类型、标题、画面里的一句、能读到的一行、这一眼新发生了什么。看不清的名字留空。画面中间的动漫角色是旁边的她，不写进观察。没有新事实就写「没变」。「在看网页」「在操作电脑」这种空话丢掉。

### 为什么这句话能交回去

理解不在眼睛里。`situation.py` 维持场景、对象和进展：换软件是场景变了，下一首歌是对象变了，同一部电影里情节往前走只是内容变了。标题没变，不等于没有新内容。对不上的一眼先稳住，不让场景卡跟着单次识别横跳。

开口仍是 dsh。闸门只丢掉明显不该交的：没变、空话、和上一眼同一件事、只有「我在陪着你」的句子。放行之后她可以说话，也可以沉默。沉默记一笔「考虑过、未说」，避免马上再交一次。用户开口会作废正在排队的主动陪看，先把这句聊完，不把刚才那句电影评论补播出来。「别说了」只停主动开口，眼睛还在。「别看了」或再按一次眼睛，陪看停掉，8766 上的进程退出。关掉小可爱时，视觉进程绑在同一个 Windows Job 里，一起退出。

采集和识别是分开的。设计上采集大约每 0.5 秒留一帧，理解时从缓冲里取一个窗口，窗口之间留重叠。识别慢的时候采集不停。超出缓冲或眼睛中断，记下 `continuity_gap`，不把缺口编成连续剧情。送进 dsh 的【现场】有长度上限，跑几个小时也不能把全部画面描述灌进上下文。

这条路能做起来，是因为每一步都已经有落点，没有为一起看新开一套大脑。

| 需要的东西 | 当时已经有的 |
|---|---|
| 一句观察进对话 | 记忆、情境、`[lookup:]` 都是「宿主查完，把事实放进现场」 |
| 她决定说不说，并带表情和镜头 | dsh 的 `chat` 技能和原来的标签解析、全双工 |
| 一个小的本机视觉模型 | MiniCPM-V 4.7 1B 只出短观察。试验进程先在 `minicpm-o-demo/v47` 跑通，再收成旁边的服务，不把试验代码塞进后端 |
| 和语音共用显卡 | 两边都落到 transformers 5.20.2 之后，B 包只带一份 PyTorch。眼睛通过 `PYTHONPATH` 用语音那一份，不再拷第二套 CUDA |
| 抓到浏览器里的视频 | DXGI 在眼睛进程里已经试过；BitBlt 不够 |
| 代码和网页不必看图 | Win32 能读到进程、标题和控件文字 |
| 歌词和台词不必从像素里认 | 环回采集加上已有的语音识别 |
| 默认不看 | 模块开关本来就是关掉等于没装 |

做不成的前提也很具体。如果 1B 必须和官方 Qwen TTS 挤在同一个 transformers 4.57 里，眼睛起不来，语音预热也会坏。如果每一帧都送进主对话，会话会被画面描述淹没，开口也会被眼睛的几十秒拖住。如果让 dsh 自己去点鼠标，就超出了「坐在旁边」这条边界，也和现有的全双工抢输入。

## 同一段里的舞台修复

PMX 的布料物理有两个会把人放大的口子，都在 `stage.ts`。

模型缩放是 0.08。`MMDPhysics` 发现缩放不是 1 时，会把 mesh 的缩放临时改成 1、把 parent 摘掉，算完再改回。初始化或步进一旦抛错，改回那一步不会执行，角色就停在 `1 / 0.08 = 12.5` 倍。关掉物理也缩不回去。现在步进放在 `holdMmdMesh` / `restoreMmdMesh` 里，抛错就关掉物理并恢复姿态，下一帧再检查缩放是不是还停在 1。

另一个口子是预热。`update` 把缩放临时改成 1 之后不刷新矩阵，连续 warmup 时下一次会以为缩放已经是 1，把刚体位置写进仍是 0.08 的骨骼。换人时如果还拿着上一个角色的物理对象去预热，新角色会被放大。现在用代数丢掉过期的物理对象，换模型或初始化失败时释放 wasm 里的刚体、碰撞配置和构造信息。不释放的话，wasm 堆大约 64MB，连换几次模型就会耗尽。

桌宠重建窗口后记住当前角色，是 `4b52fd4`。那是状态没随窗口走，不是模型管线。
