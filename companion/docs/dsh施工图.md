# dsh 接进小可爱

## 2026-11-02：统一聊天代理

以下是当前实现；后面的 10 月施工记录保留为历史背景。

- 开关打开且模型支持 Messages 时，普通聊天、重说、看牌收线、欢迎、续聊、告别、摸一下、Code 伴侣和陪看共用同一条角色会话。宿主事件明确标注，不伪装成用户发言。陪看的事实核验、修复一次和 epoch 过滤继续保留。
- 一轮的配置准备、会话选择、流订阅、执行、退订和计数在同一个串行区间内。HTTP 转发绑定请求开始时的订阅者，旧响应不会交给下一轮。UTF-8 使用增量解码。
- 断开、打断、超时和过期候选立即停止向宿主输出。当前锁定的 SDK 没有公开的单轮取消方法，因此关闭占用中的运行时；下轮重新拉起。取消标记按会话代数落盘，即使生成已经完成但没有交付，也不会恢复那段未交付历史。
- `/message/{id}` 的已说内容修正和清空历史同时使 dsh 旧会话失效；下一轮由宿主当前记录重新播种。宿主消息是用户实际听到内容的依据。
- 稳定身份按内容哈希版本化，变更时换会话。边界、时间、记忆、临时身份、当前任务和资产名单属于动态现场，每轮刷新。
- 按保守的 UTF-8 字节估算累计上下文，预算为 20,000 token，36 轮仍作兜底。换会话时带最近十轮，以及从宿主记录提取的有界偏好、约定原话；每类最多八条，每条 240 字。摘录不是事实推断，以最新现场为准。原有长期记忆模块继续工作。
- profile 禁用文件、命令、任务、计划、子代理、插件管理等模型工具，保留 `skill`。关闭编程身份和运行目录提示。真实 runtime 配本地假 Messages 服务的测试会检查实际工具列表。
- API Key 的哈希和 profile 内容参与运行时配置比较；换钥匙会重建进程，哈希不写入日志。
- 启动和相关设置更新后在后台预热本地 runtime，不发送模型 prompt。转发层复用上游 HTTP 连接，各请求仍独立传入凭据；转发前移除 `dsh_plugin_packages` 和 `dsh_session_log`，保留正常消息、技能工具和思考参数。

真实请求分段测速使用 `backend/tools/benchmark_chat_agent.py`，默认使用固定模拟人设和三轮模拟对话，不读取用户保存的人设或聊天。`--dsh-only --prewarm` 验证预热后的路径。输出只含耗时、请求大小、消息数和测试回复，不含密钥；结果以时间戳保存到 `backend/data/chat-agent-benchmark-*.json`。首个 TTS 单元的时间只代表文本已可送合成，不代表音频已经播放。

验证入口：`backend/.venv/Scripts/python.exe -m pytest backend/tests/test_harness.py backend/tests/test_stream_tap.py backend/tests/test_harness_runtime.py`（从 companion 目录运行）。测试只使用本地假模型服务，不消耗远端模型额度。

### 自然动作与视觉按需启动

- Harness 路径下，游戏启动不再在 `hooks.after_messages` 用句式正则预先执行。dsh 的 `play` 技能结合用户这句和上下文返回 `[play:正式游戏名]`，宿主继续通过已有游戏库/平台启动器执行。仅讨论、否定或假设不启动；没有明确游戏对象时追问。
- `watch` 在视觉环境已配置时就可供 dsh 使用，无需先打开陪看。能力检测只检查配置和环境，不启动进程、不截图；实际启动失败时返回真实状态，不声称硬件一定支持。
- `[glance:问题]` 只看一次；`[glance:陪看 问题]` 和 `[glance:开启]` 开始持续陪看；`[glance:关闭]` 停止。只说要玩游戏不自动打开视觉；同时要求陪玩时，先执行游戏启动，再准备视觉。
- 分流由模型选择动作。宿主额外阻止将金价、天气、新闻、攻略等公共信息请求误当截图；明确指向屏幕或截图中的内容时才允许读这些信息。无对象的「你看一下」在没有屏幕上下文时转为追问。旧的关键词自动开启和 `glance_from_user` 强制兜底不用于 Harness 请求。
- 真实模型语义检查：`backend/tools/check_agent_intents.py`。使用固定模拟对话，只收集动作，不执行游戏启动或截图；宿主协调器另有 `/api/chat` 的模拟后端测试，覆盖先开游戏再陪看、只开游戏不看、金价误选视觉的纠正和无对象追问。

## 原始施工记录

2026-10-21。内核用 DeepSeek Harness（`dsh`）。小可只站在它公开的那一层上：Python SDK、长驻的 `dsh --profile sdk`、换行 JSON-RPC、显式的 `dsh_home`。内核按它自己的节奏升级，小可不钉死某一版。

舞台、语音、表演标记解析仍是小可的。dsh 负责想和说。技能目录上面那一层路由是 harness 自己的：每轮只看见名字和 `description`，对上了才读正文。小可不另写意图分类器。

## 挂法

1. **一个长驻进程。** 模块打开后，后端拉起一次 `deepseek-harness-sdk` 里的 `dsh --profile sdk`，关掉模块或退出程序再收掉。不走 `headless`，不开 `dsh web`。项目若在 C: 以外的盘，子进程的当前目录改到 C: 上的一个空目录，会话目录仍留在数据目录里。这是 Windows 上快照加载 koffi 的已知问题。
2. **技能在内核外面。** 仓库里的 `SKILL.md` 同步到本机数据目录的 `dsh/skills/`。这个目录就是这次运行的 `DSH_HOME`，不碰用户的 `~/.dsh`。工作目录是旁边的空 `dsh/workspace`，不指向安装目录，也不指向源码仓库。
3. **聊天、跳舞、看牌、画画是四条技能。** 目录只给模型看名字和 `description`，对上了才读正文。`chat` 管闲聊和表演标记。`dance` 只管对方点名要跳，文件名仍放在【现场】。`tarot` 只管怎么讲已经摊开的牌；发牌、切牌、翻面仍是代码，这一轮该讲哪张写在【现场】。`draw` 只管按画面内容开口，并写 `[draw:画面]`。对方这句已经说出画面时，舞台先把这句说出来并开画，不等模型把整段写完。出图是代码，竖图用较小尺寸。等待时牌位先亮着，图贴上后再说一句。图固定在屏幕右侧、上下居中，不跟着人走，点一下放大。同一张写入证物相册，不走进看牌的流程。许愿不是技能：池子、道具和枚数由盒子算，口头那句在进对话前就被认走，模型只补一句带数字的旁白，说错就丢掉。当前内核给模型看的目录没有 `whenToUse`，所以「什么时候用」写在 `description` 里。技能不会每轮自动灌进提示词。
4. **以后陪着看是下一条技能。** 同一目录再放一份 `skills/watch/SKILL.md`，`description` 写清什么时候看屏幕。游戏、视频、屏幕上的活都走这一份。看懂画面如果要工具，写成和 `lookup` 一样的标记，由宿主去看，不把像素送进会话。这一刀不放空文件，避免目录里多一个没写完的名字。
5. **交回现有管线。** 模型正文仍进现在的标签解析、全双工和 TTS。`[emo:]` 这些标记还是导演的，不由 harness 去拧骨骼。
6. **两套大脑不要同时答一句。** 模块开着时，用户正常开口走 dsh。失败就在这轮报错，不悄悄退回旧的 `llm.py`。模块关着，一切照旧。

密钥和地址用设置里已有的 AI 对话。SDK 把 `api_key` / `base_url` 放进子进程的 `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL`。模型名用设置里的。

## 还没做

- [ ] 陪着看的技能。等「看一眼」能交出一段观察之后再写 `skills/watch/SKILL.md`。游戏、视频、屏幕上的活都是这一份，目录里不另放 `game`。口吻和什么时候闭嘴写在技能里。不在对局里代操作。接法见 [MiniCPM-V 4.7 1B 与小可爱](./MiniCPM-V-4.7-1B-and-xiaokeai.md)。
- [ ] `session.status` 接到 Code 伴侣那块牌子上。现在用户开口已经能演，牌子还没跟着 harness 的 running / idle 亮。
- [ ] 欢迎、续聊、告别改成同一条 `chat` 技能里的步骤。现在它们还走旧模型，避免 dsh 冷启动时舞台先哑掉。
- [x] 体验包带走 runtime。可执行文件在 `deepseek_harness_runtime/runtime/`，精简 A 包时不把它挪到 B，也不当开发残留删掉。
- [ ] 文本若只有整段 `assistant/message`、没有增量，开口会等这轮闲下来。协议若以后带增量，现有队列直接接着喂，不用再加一层。

## 不要做

- 不要在小可里写「这句话像聊天还是像看游戏」的分类器。`description` 和 `whenToUse` 就是路由。`/chat` 这种点名留给以后的按钮，需要时由界面直接注入正文。
- 不要把导演手册再抄进【现场】。标记规矩在 `chat` 技能正文里，选中才读。
- 不要跟 master 源码，也不要改 Cordis、profile 目录里的实现来「接得更死」。技能文件和 SDK 调用是升级跟得上的那一面。
- 不要把 dsh 嵌进当前推理进程。它是旁边的子进程。ASR / TTS 的包版本不动。
