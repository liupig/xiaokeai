## 分工

| | MiniCPM-V 4.7 1B | 小可爱 |
|---|---|---|
| 角色 | 眼睛 | 人 |
| 输入 | 一张图，或按时间排的几秒画面 | 眼睛交来的一句观察，加上现有人设、记忆、情境 |
| 输出 | 一两句现场情况 | 语音、口型、表情、动作、运镜 |
| 跑在哪 | 旁边单独进程。本地试验在 `minicpm-o-demo/v47`，整目录不入库 | 现有后端和舞台 |
| 不能做的 | 当主对话模型、长逻辑、工具调用、替用户操作 | 自己看屏幕。现在的摄像头是动捕，不是看懂 |

1B 的语言模型骨干是 Qwen3.5，纯文字也能答，只够短句。主聊天继续走现在的 OpenAI 兼容地址。

它的原生请求是一组对话消息，不是小可爱现在的聊天接口：

```python
messages = [{
    "role": "user",
    "content": [
        {"type": "image", "url": "这一帧"},
        {"type": "text", "text": "他具体在干什么？"},
    ],
}]
```

画面连续在动时，把 `image` 换成 `video`，帧按时间排。`transformers>=5.18`，`AutoModelForImageTextToText`，不需要 `trust_remote_code`。

## 本地试验里已经试过的

这些只在本机 `minicpm-o-demo/v47`，不在仓库里。接进小可爱时再写成正式模块，不要把试验进程原样塞进后端。

- 连续看桌面。抓屏用 DXGI（合成后的画面）。旧的 BitBlt 抓不到浏览器里硬件解码的视频，整屏一平均还会把小窗口里的变化当成没变。
- 静止时看一帧，说具体软件、标题和动作。「在看网页」「在操作电脑」这种空话丢掉。
- 画面连续在动时，连看大约 4 秒，跟着讲这几秒里的动作、字幕和换场。只说「在看视频」丢掉。
- 和上一眼是同一件事，只记「没变」，不往记录里堆。
- 最近几条观察会带进下一次，让它知道刚才已经说过什么。

## 怎么进 dsh

眼睛对小可爱只交一句，例如：「B 站这一段里，字幕写着某某，画面切到了街景。」像素不进会话。dsh 看不见图，只看见这句。做法和 `lookup` 一样：模型不自己去看，宿主看完把事实放进【现场】。

【现场】里单列一块，标题就叫【眼前】。身份、记忆、情境仍走现在的 `host_brief`。1B 不写 `[emo:]`，那些标记留在技能正文里，由 dsh 写。

两条入口，都进同一条会话 `xiaoke-{角色 id}`：

1. **对方让看，或点了「看看屏幕」。** 这轮本来就是 `mode=user`。按钮路径上，宿主先看完，【眼前】已经在【现场】里。口头说「看看」时，技能让她先写 `[glance:]`，宿主截一帧交给 1B，下一轮再把观察放进【现场】开口。铺垫只说「我看看。」这一轮不许编画面。
2. **开关开着，屏幕变了，对方没说话。** 「没变」、空话、和上一眼同一件事，宿主丢掉，不开会话。真变了，才往这条会话再送一轮，【这句】写明对方没开口。不走现在的 welcome / proactive。那几条还在旧模型上，两套大脑会各说一句。

技能只留一份：`skills/watch/SKILL.md`。dsh 施工图里预留的游戏陪玩就是这一份，目录里不再另放 `game`。`description` 写清：【现场】有【眼前】，或对方让你看屏幕、陪着看的时候用；闲聊、看牌、跳舞、画画、查现况不要用。口吻和什么时候闭嘴写在正文里。宿主不写「这句话像不像在看屏幕」的分类器，路由仍是技能目录。

- [x] 模块 `glance`，默认关。设置里的「看一眼」。关掉等于不截屏、不把 `watch` 放进技能目录、不写【眼前】。打开后下一轮对话才生效。
- [x] 后端用 HTTP 向本机眼睛进程要一句观察，不 import 视觉模型。
- [x] 这一眼不进长期记忆。开口、打断、排队仍是现有全双工。眼睛不许自己播 TTS，也不去点。
- [x] 问「我在干嘛」看一帧。让她在屏幕上找东西，看一帧并说在哪一块。说陪看剧，跟这几秒。
- [ ] 她正在说，或这一轮 dsh 还没答完：新观察只留着，并进下一轮【眼前】。T-111。
- [ ] 塔罗进行中、跳舞中、Code 伴侣开工中，不送「屏幕变了」那一轮。T-111。
- [ ] 「看看屏幕」按钮。用户能圈定只看哪一块。T-112。
- [ ] 「看看我」走摄像头，不和动捕抢。T-104。

## 玩法

都是「她坐在旁边」。变了才说话，没变就陪着。

### 一起看

- [x] 对方说陪看剧：跟这几秒，讲看得见的内容。T-019。
- [ ] 同一段不重复，换场才接。比赛、直播、吐槽、夜戏。T-113。

### 一起玩

- [ ] 旁观、抽卡、暂停猜下一秒、音游跟拍。T-113。不代打。

### 陪着干活

- [x] 让她找屏幕上的东西在哪，例如百度网盘在桌面哪里。只说位置，不去点。T-019。
- [ ] 报错那一行、教程下一步、剪片、换商品页再比较。T-113。

### 桌宠日常

- [ ] 路过、久别第一眼、提醒时画面还停着、说记下才进证物。T-114。

### 人设

- [ ] 情境卡开着时，用今晚这场戏的身份看屏幕。T-114。身份仍是现有扮演层。

## 顺序

1. 口头三句。已完成，T-019。
2. 闲时真变了才开口。T-111。
3. 按钮和圈定窗口。T-112。摄像头「看看我」仍是 T-104。
4. 比赛、旁观、干活这些具体喊法。T-113。
5. 路过、久别、提醒、证物、情境卡。T-114。

## 不做

| 项 | 原因 |
|---|---|
| 用 1B 替换主对话模型 | 容量只够短观察。人设和表演会变薄 |
| 装进当前后端进程，或装进 dsh | 和现有 TTS 的 transformers 版本打架。dsh 也看不见像素，图送进会话没有用 |
| 在宿主里判断「这句是闲聊还是看屏幕」 | 路由是技能的 `description`。宿主只决定截不截、变没变 |
| 屏幕变了走旧的 proactive | harness 开着时那是另一套模型，会和 dsh 各说一句 |
| 让 1B 写表演标记 | 标记是 dsh 的。眼睛只出观察 |
| 后台无开关地一直截全屏 | 先要开关、先要能圈范围 |
| 代打、代点、代买装备 | 不是陪伴 |
| 把每一帧都念出来 | 用户会烦。同一件事只允许「没变」 |
| 两路同时抢摄像头 | 动捕占摄像头做骨骼。看屏幕是另一路 |
