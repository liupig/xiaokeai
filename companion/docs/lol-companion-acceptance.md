# LoL 陪玩联动交付与验收

## 产品行为

角色以用户当下目标为中心。API负责身份和数值，视频提供画面经过，用户语音提供情绪和交流意图。击杀不等于操作精彩，死亡不等于用户难过。不得从镜头中心认定玩家身份。

玩家击杀、被击杀和助攻映射成英雄事件，按事件编号过滤；超过8秒的击杀不再作为新事件。API快照超过5秒不提供实时事件。API与视频时间差超过3秒时禁止联合归因；时间接近仍不能证明技能命中和战术因果。

当前采集仍绑定视觉轮次：尚无独立API轮询服务，因此不能承诺上述时间阈值内必定发言。事件过滤是观察级，不是播放确认级；用户打断后不保证重投。

## 可观测依据

每轮sight结果含fusion.aligned、api_age、event_ids、events。与现有trace关联检查事实、生成、排队和实际播放；不得只以模型生成了文本认定成功播报。禁止记录完整账号标识作为验收附件；只保存必要的匿名事件和经允许的回放。

## 自动验收（每次修改必须运行）

- 击杀、死亡、助攻分别归属，未识别单位保持未知。
- 相同事件重复投递不再次生成新事件。
- 视频延迟、API过期不产生跨来源因果。
- 新局时钟回退后允许重复事件编号，不继承上一局事件。
- 无接口、缺字段不影响普通视觉陪伴。
- 个人战绩、团队击杀和目标资源分别表达；不虚构总经济和胜率。

命令：在backend目录执行 `.venv/Scripts/python.exe -m pytest tests/test_league_fusion.py tests/test_league_scores.py tests/test_companion_contract.py tests/test_glance_sense.py tests/test_sight.py tests/test_play.py -q`。

## 商业发布门槛（待实际测量，不能用单元测试代替）

1. 经同意采集不少于10局、至少3种位置和2种模式的回放，包含至少100个玩家相关事件。训练模式只验证接口，不替代真实对局。
2. 标注事实准确率≥99%；玩家身份误归属、虚构技能命中、虚构经济差均为0例，否则阻断发布。
3. 同一事件重复播报≤1%；已取消/过期事件播放0例；API中断恢复和新局重置至少各覆盖10次。
4. 在声明的硬件、视觉模型、对话模型和网络条件下，记录事件发生到首段声音的P50/P95。发布目标P95≤8秒；做不到应明确配置限制并优化采集，禁止宣称实时达标。
5. 用户说话时不抢话；安静模式主动播报0次；交火期间不连续追问。分别用语音打断、手动静音和暂停测试。
6. 至少5位目标用户盲测，陪伴自然度、情绪贴合、打扰控制分别评分，平均≥4/5且无单项低于3/5。失败回应不得责备，成功回应需有具体依据。
